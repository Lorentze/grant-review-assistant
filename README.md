# 基金申请书整理与评审助手

一个面向科研基金申请书批量整理的 Streamlit Web 应用。代码可托管在 GitHub；对于未公开申请书，建议在本机或单位内网运行。

## 已实现的 MVP 功能

1. 同时上传多个 PDF；支持统一密码或逐文件密码。
2. 在内存中解密 PDF，不将密码写入文件、日志或数据库。
3. 下载单个解密 PDF 或全部解密文档 ZIP。
4. 自动识别并提取 NSFC 2025/2026 通用申请书和海外优青申请书。
5. 规范化整理申请人、项目、教育与工作经历、基金主持/参与、代表性论文、预算和正文关键区块。
6. 对基金经历区分：主持/参与、NSFC/其他、在研/结题。
7. 对论文区分：申请书自述总量、代表性论著、第一/通讯作者、年份分布和近两年清单情况。
8. 允许人工校正核心字段。
9. 可选调用 OpenAI Responses API，生成客观的优点、不足、风险和初评。
10. 用户完成分项评分、综合等级和资助意见后，按批次排序并生成正式评语。
11. 输出多工作表 Excel、结构化 JSON 和解密文档。

## 为什么不是纯 GitHub Pages

GitHub Pages 只能托管静态 HTML/CSS/JavaScript，无法直接运行本项目的 Python 解密、PDF 解析和 Excel 生成逻辑。推荐方式是：

- **代码托管**：GitHub；
- **敏感材料使用**：本机或单位内网 Docker；
- **非敏感演示**：Streamlit Community Cloud 等 Python 托管平台。

## 本地运行

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
streamlit run app.py
```

浏览器打开 `http://localhost:8501`。

## Docker 运行

```bash
docker compose up --build
```

浏览器打开 `http://localhost:8501`。

可选设置模型 API Key：

```bash
export OPENAI_API_KEY="你的密钥"
docker compose up --build
```

也可以不设置环境变量，在网页中临时输入。API Key 不写入导出文件。

## Excel 结构

- `项目总表`：每个申请项目一行，不包含摘要；
- `教育与工作`：教育、博士后与任职经历；
- `基金主持参与`：每项基金逐条列出；
- `论文发表`：代表性论文及其余论著逐条列出；
- `经费预算`：预算科目；
- `AI初评`：优点、不足、风险、基金与论文评价；
- `人工评分`：分项评分、综合等级、资助意见、批次排序、最终评语；
- `提取证据`：字段页码、证据片段和置信度；
- `正文区块`：供复核和 AI 评价使用的关键正文区块。

## 数据与隐私边界

- 密码只在当前 Python 进程内使用，不写入磁盘或日志。
- Streamlit 会在当前会话内持有上传文件和控件值，因此远程服务器运营者理论上可以接触进程内数据。
- 使用 AI 时，仅发送结构化字段和必要正文区块，不发送 PDF 文件本体；这些文本仍会离开本机并发送到模型服务。
- 对未公开、敏感或涉密申请书，应关闭外部 AI，并采用本地部署；后续可接入本地大模型。

## 当前解析策略与局限

解析采用“格式识别 + 规则提取 + 证据页码 + 人工校正”模式，而不是让大模型直接猜表格字段。这样更可复核，也能减少模型幻觉。

当前优先支持 born-digital PDF。扫描件、复杂表格和新版本模板可能需要新增适配器。任何“未列出”的信息都不会被自动解释为“没有”。

## 扩展新的基金格式

在 `src/grant_review/extractors/` 增加新的适配器，并在 `detector.py` 中加入识别规则。建议每个适配器至少提供：

- 封面和基本信息字段；
- 申请人简历边界；
- 基金项目列表；
- 论文列表；
- 预算；
- 与该项目类别相匹配的正文区块。

## 建议的下一步迭代

1. 增加自然科学基金以外的项目模板。
2. 增加扫描件 OCR 与表格坐标提取，但仅对无法直接提取文本的页面启用。
3. 增加期刊分组的用户自定义配置，不在代码中硬编码“顶刊”。
4. 增加本地大模型接口和完全离线模式。
5. 增加批次级相似性检测、指标对齐和匿名比较。
6. 增加人工修改历史与审计日志，但不记录密码和 API Key。
