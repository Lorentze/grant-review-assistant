# 基金申请书本地整理与评审助手

这是一个**不依赖远程服务器的本地桌面应用**。界面使用本地 HTML/CSS/JavaScript，PDF 解密、文本提取、字段整理、Excel 生成与批次保存由同一台电脑上的 Python 引擎完成。

最终用户不需要安装 Python、配置环境、访问管理员链接，也不需要理解 GitHub。拿到 Windows 或 macOS 安装包后，解压并双击即可。

## 教授端实际使用流程

1. 双击 `GrantReviewAssistant.exe`（Windows）或“基金评审助手.app”（macOS）。
2. 一次选择一份或多份基金申请书 PDF。
3. 输入统一 PDF 密码；个别文件密码不同时，在对应文件一行单独填写。
4. 选择本地输出文件夹。
5. 点击“一键解密、整理并生成初评”。
6. 复核申请人、项目、基金经历、论文、预算和 AI/规则初评。
7. 填写分项得分、综合等级、资助意见和备注。
8. 生成整个批次的正式评语，并在本地打开 Excel。

整个过程中不需要管理员发送网址，也不需要启动命令行。

## 本地保存内容

每个批次会在用户指定位置新建一个文件夹：

```text
2026量子信息面上项目/
├── 解密PDF/
│   ├── 申请书1_decrypt.pdf
│   └── 申请书2_decrypt.pdf
├── 基金申请书汇总.xlsx
└── 批次数据.json
```

`批次数据.json` 用于下次继续评分。它保存结构化提取结果、人工评分和评语，但**不保存 PDF 密码或 API Key**。

## 隐私边界

### 默认本地规则模式

- PDF 文件不上传；
- PDF 密码不写入磁盘；
- 解密和解析完全在本机完成；
- Excel 和 JSON 只保存在用户选择的文件夹；
- 不调用任何网络服务。

### 本地 Ollama 模式

- PDF、文本和模型均在本机；
- 需要用户已经安装 Ollama 并下载中文模型；
- 应用只访问 `127.0.0.1` 的本地模型服务。

### OpenAI API 模式

- PDF 文件和 PDF 密码仍不发送；
- 仅在用户明确勾选确认后，发送规范化字段和必要正文片段；
- API Key 仅存在于当前操作内存中，不写入 JSON、Excel或设置文件；
- 高保密材料可一直使用本地规则或本地 Ollama 模式。

## 当前提取内容

- 项目名称、申请代码、接收编号、资助类别、经费与研究期限；
- 申请人、职称、依托单位、教育经历、博士后及工作经历；
- 合作单位、团队规模与高级职称人数；
- 国家自然科学基金与其他项目，区分主持/参与、在研/结题；
- 代表性论文和其他论文，区分申请书自述总数与实际列出的代表作；
- 代表作年份分布、作者角色及近期成果提示；
- 设备费、业务费、劳务费、合作转拨等预算信息；
- 立项依据、研究内容、创新点、研究基础、工作条件等正文区块；
- 本地规则初评、可选 AI 初评、人工评分、批次排序和正式评语。

摘要可以被解析，但不作为 Excel 总表的核心字段。

## 为什么不是直接双击一个裸 `index.html`

纯浏览器页面无法直接复用现有 Python 解析器，而且浏览器沙箱对本地文件读写、PDF 解密算法、批量目录输出和大型模型调用有较多限制。当前方案把本地 HTML 界面与 Python 引擎一起封装为桌面应用：

- 对用户而言仍是网页式界面；
- 不需要远程服务器或本地端口；
- 不需要安装开发环境；
- 能直接使用成熟的 `pypdf`、`openpyxl` 和申请书格式适配器；
- 文件始终由用户自己的电脑读取和保存。

## 源码目录

```text
desktop_app.py                  # pywebview 桌面入口
ui/
  index.html                    # 本地 HTML 界面
  styles.css
  app.js
src/grant_review/
  local_backend.py              # 本地批次处理服务
  local_review.py               # 完全离线的规则初评与评语
  ai_review.py                  # OpenAI / Ollama 可选接口
  pipeline.py                   # PDF 处理流水线
  extractors/                   # 不同申请书格式适配器
  excel_export.py               # Excel 导出
GrantReviewAssistant.spec       # PyInstaller 打包配置
.github/workflows/              # 自动构建 Windows/macOS 包
```

## 开发模式运行

开发者才需要执行以下命令；教授端不需要。

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python desktop_app.py
```

## 自动构建发布包

将仓库上传到 GitHub 后，在 Actions 中运行 `Build desktop apps`，即可获得：

- Windows 便携版；
- macOS Intel 版；
- macOS Apple Silicon 版。

给仓库打 `v0.1.0` 之类的标签时，工作流还会自动创建 Release 并附上三个压缩包。用户只需拿到相应压缩包，解压后双击。

正式大范围分发前，建议为 Windows 程序和 macOS 应用进行代码签名；这能减少系统对未签名应用的安全提示。

## 已知边界

- 当前主要面向可直接提取文本的 PDF；扫描件 OCR 尚未作为默认流程。
- 申请书格式变化较大时，需新增或调整格式适配器。
- “代表性论著清单中未列出某年论文”不等同于“申请人该年没有发表论文”。程序会保留这一证据边界。
- AI 初评只提供辅助材料，最终等级、资助意见和正式评语仍由评审专家决定。
